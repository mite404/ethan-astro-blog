A week-long interview prototype built around one brief: _"Make agent work more legible for
non-technical people."_ I built a [knowledge-work desktop](#case-threads) where an agent works
through threads, text and UI cards. I matched the company's architecture so the interface could move
onto their stack without changes, and I recorded every design decision as I went.

The model never writes UI. It describes data, and the app renders that data with a small set of
tested cards, so people can follow [how the agent got there](#case-receipt). Anything those cards
can't show falls back to a plain table instead of improvised interface. The server sets limits on the
agent and stops offering a tool once that tool keeps failing, so people see
[named steps and outcomes](#case-work) instead of a stream of retries. Automated checks catch visual,
accessibility and [motion](#case-motion) drift, and a human has the final say on what counts as
correct.
