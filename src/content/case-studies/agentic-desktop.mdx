An agentic [knowledge-work desktop](#case-threads), prototyped end to end for a design engineering
interview in about a week. I mirrored the company's docs, data policies and architecture, separating
daemon and gateway so the UI could move onto its stack unchanged.

_"Make agent work more legible for non-technical people."_

---

01 · ADR-014

### Flexible output, predictable cards

A validated catalog keeps the model from inventing unfamiliar UI.
[`resolve()`](#case-schema) rejects cards outside its schema. Familiar cards let people inspect
[how the agent got there](#case-receipt).

---

02 · ADR-155 + ADR-157

### Keep the loop where the key and cost are

I rejected a browser-owned loop. The gateway streams Kimi through OpenRouter, limits rounds and
[withdraws tools](#case-loop) after two failed calls. The UI shows
[work steps and outcomes](#case-work); the gateway contains repeated failures.

---

03 · ADR-065 + ADR-051

### Taste plus measurement, with a human final say

My CLI and review app compare Storybook captures with approved references and check tokens and
accessibility. [Motion gets measured, too](#case-motion). Checks catch drift from human and agent
changes; only a human can approve a new baseline.

<Asset id="case-schema" label="Schema validation pseudocode">

```typescript
function resolve(output: unknown) {
  const card = catalogSchema.parse(output)
  return renderCatalogCard(card)
}
```

<Asset id="case-loop" label="Tool withdrawal pseudocode">

```typescript
try {
  await runTool(call)
} catch {
  const count = (failures.get(call.name) ?? 0) + 1
  failures.set(call.name, count)
  if (count >= 2) offeredTools.delete(call.name)
}
```

Illustrative pseudocode based on ADR-157. The gateway owns this loop and its round limit.
